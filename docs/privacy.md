# Privacy and data handling

Paprika's browser converter processes documents locally. Selecting or converting a PDF does not upload its bytes to Paprika, Cloudflare, or another service.

## What stays local

- The selected PDF is read by JavaScript in the current browser tab.
- Conversion runs in a Web Worker with the WebAssembly module shipped with the site.
- Source previews and generated previews use browser-owned object URLs.
- The generated EPUB or PDF is downloaded only when the user chooses to save it.
- The application has no Worker script, upload endpoint, analytics, database, object storage, telemetry SDK, or third-party runtime API.
- The Content Security Policy limits network connections to the site's own origin.

Reloading or closing the tab ends the application session and the app releases its object URLs and worker where the browser permits. This is not a secure-erasure guarantee: browsers, operating systems, extensions, crash reporters, swap, backups, and downloaded files have their own retention behavior.

## What reaches the network

Opening the site makes ordinary HTTPS requests to Cloudflare for static HTML, CSS, JavaScript, WebAssembly, and icons. Cloudflare and network operators can observe normal request metadata such as IP address, time, requested asset, user agent, and transport information according to their own policies. Paprika does not include document bytes in those requests.

The source PDF preview and generated EPUB/PDF preview use local `blob:` URLs. The application does not follow remote image references from source PDF text into EPUB content.

## Preview sandbox boundary

Generated EPUB chapters are shown in an iframe sandboxed with `allow-same-origin` but without `allow-scripts`, forms, popups, navigation, or downloads. Chapter markup is generated by Paprika and active source-document markup is escaped or removed before packaging.

Chrome's built-in PDF viewer does not load a PDF in a sandboxed iframe. Paprika therefore removes the iframe sandbox only while it shows a source or generated PDF `blob:` URL. Those bytes are local, but the browser's PDF viewer and installed extensions are then part of the trust boundary. The separate **Open PDF in a new tab** link uses `noopener noreferrer`.

## User responsibilities

- Review browser extensions and device policies before processing sensitive documents.
- Save generated files only to an appropriate location.
- Use the native CLI on a controlled machine when browser or network metadata is unacceptable.
- Clear downloads or other local copies according to the device's retention policy.

Report a privacy regression as a security issue. Do not attach a sensitive source document; use a synthetic reproducer.
